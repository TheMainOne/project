# ECN Agent v0.5

Локальная панель наблюдения за рабочей **Engineering Change Form (ECF)**. Sheet ID `5485143814104964`.

**Для установки ИИ-разбора и базы знаний открой [AI_RU.md](AI_RU.md).** Инструкция предыдущего обновления находится в [UPDATE_RU.md](UPDATE_RU.md). Существующие `.env`, база и журнал сохраняются при обновлении. Ниже — устройство модуля и инструкция первого запуска.

## Возможности

- Компактная таблица в стиле Smartsheet: номера строк, закреплённый номер ECN, статусы, площадки, материалы и описания.
- Поиск, фильтры, сортировка по порядку ECF, изменению строки и активности обсуждений; страницы по 100 строк.
- Боковая карточка с данными ECN, описанием изменения и текущими согласующими.
- Обсуждения ECN с авторами, датами, ответами и датами редактирования.
- Обнаружение новых, отредактированных и исчезнувших комментариев при каждой проверке.
- Сохраняемые отметки новых/изменённых сообщений, фильтр «Новые комментарии».
- Вложения строки и её комментариев: скрепка со счётчиком, фильтр «С вложениями», отдельная вкладка с названием, размером, автором и датой.
- Открытие файла или внешней ссылки по свежему адресу из Smartsheet; журнал добавлений, удалений и изменений метаданных вложений.
- Журнал последних 100 событий в интерфейсе; более ранние события остаются в SQLite.
- Пауза, ручная проверка и восстановление после остановки.
- Автоматический номер по дате создания для строк с пустым `ECN Number` и статусом `Initial Review`, с учётом рабочей ECF и ECN ARCHIVE.

При включённой автонумерации агент записывает `ECN Number`. Пользователь также может отправить комментарий из карточки ECN. Вкладка «ИИ-разбор» по запросу пользователя обращается к OpenAI и сохраняет предложение локально.

## Первый запуск

Нужен Node.js 24 или новее. Для этого комплекта подходит Node.js 24 LTS с [официального сайта](https://nodejs.org/en/download).

Помести папку `agents` из архива в корень локального `project`. Должен появиться путь `project/agents/ecn-agent/package.json`.

В Windows CMD из корня `project`:

```cmd
cd agents\ecn-agent
copy .env.example .env
notepad .env
```

На macOS/Linux вместо `copy` используй `cp`. Шаблон копируется только при первой настройке. Если `.env` уже заполнен, используй его.

В `.env`:

```dotenv
SMARTSHEET_API_TOKEN=твой_токен_Smartsheet
ECN_PORT=4310
ECN_POLL_SECONDS=120
ECN_AUTO_NUMBER=true
```

Токен хранится в **`agents/ecn-agent/.env`**. Корневой `project/.env` относится к основному приложению. `.env.example` — шаблон с пустым токеном, пригодный для Git.

Из папки `agents/ecn-agent`:

```cmd
npm start
```

Открой [http://127.0.0.1:4310](http://127.0.0.1:4310). Если PowerShell блокирует `npm.ps1`, запускай `npm.cmd start`. Зависимости входят в Node.js, установка дополнительных пакетов не требуется.

Пока агент работает, терминал должен быть открыт. Для остановки нажми `Ctrl+C` и дождись выхода. Чтение одной таблицы ограничено 90 секундами; перед завершением агент дожидается текущего запроса и проверки уже отправленной записи. При сне или выключении ноутбука наблюдение приостанавливается. После запуска приложение получает новый снимок; промежуточные изменения между проверками могут быть не видны.

## Работа с панелью

Номер ECN открывает вкладку «Данные ECN». Значок обсуждения открывает вкладку «Комментарии». Вторая вкладка автоматически показывает новые данные после успешной проверки. Поиск работает по номеру ECN, материалу, описанию материала, площадке, статусу и инициатору.

Синий индикатор означает новые или изменённые комментарии, которые ещё не открывались в этой локальной панели. Первоначальная загрузка существующей переписки создаёт исходное состояние без уведомлений о каждом старом сообщении. Последующее открытие вкладки «Комментарии» сохраняет отметку прочтения именно показанного снимка. Если данные успели измениться, новый снимок остаётся непрочитанным до отображения. Это локальная отметка, общая для окон этой панели; она не изменяет Smartsheet.

Обсуждения упорядочены по времени последнего добавленного сообщения, ответы внутри обсуждения — по дате создания. Дата правки показана отдельно. Авторское форматирование HTML не исполняется: тексты выводятся как обычный текст.

«Пауза» сохраняется после перезапуска. Выполняющаяся проверка завершается. «Проверить сейчас» на паузе выполняет один цикл. «Продолжить» возобновляет автопроверку. Интервал по умолчанию 120 секунд отсчитывается после завершения предыдущего цикла.

При включённой автонумерации цикл включает присвоение номеров. Это относится и к кнопке «Проверить сейчас». Пауза останавливает следующие циклы; выполняющийся цикл завершается.

После отправки комментария панель перечитывает ECF и обсуждения. Такое обновление работает и на паузе. Нумерация запускается при старте или возобновлении наблюдения, по таймеру и кнопкой «Проверить сейчас».

Если результат отправки неизвестен, кнопка «Проверить результат» сверяет сохранённые ID с обсуждением нужной строки и проверяет текст комментария. Для отправки с файлом сверяются также имя вложения и его привязка к комментарию. Для этой сверки агент выполняет запросы GET. Если сохранился только ID нового обсуждения, агент может подтвердить его единственный исходный комментарий по тексту и времени создания. Старую операцию без необходимых данных можно проверить вручную в Smartsheet.

«Активные ECN» исключает статусы `Complete and Closed`, `Deleted/Canceled`, `Declined`. Остальные строки доступны через «Все строки». Время создания/изменения строки берётся из Smartsheet и не подменяется временем сообщения. Пустая площадка остаётся пустой; агент не угадывает её.

## Автоматическое присвоение номера

В `agents/ecn-agent/.env` установи `ECN_AUTO_NUMBER=true` и перезапусти агент. Без этой настройки или при `false` сохраняется режим наблюдения. В панели включённый режим обозначен «Автонумерация».

Кандидат определяется **ровно двумя условиями**: пустая ячейка `ECN Number` и статус `Initial Review` (регистр и внешние пробелы статуса не учитываются). Заполнение Requested By, описания или Item Number не требуется. Нумеруются также подходящие заявки, уже существовавшие до включения. Формулы, ссылки и любые существующие значения в ячейке номера не перезаписываются.

Формат — `YYYYMMDD-NN`: дата `row.createdAt` по `America/New_York`, затем отдельный счётчик этого дня с минимум двумя цифрами. После `99` идёт `100`. Например, для заявки от 20 ноября при максимальном номере `20261120-03` следующий номер будет `20261120-04`, даже если обработка происходит 21 ноября. В пределах цикла заявки обрабатываются по дате создания и порядку строк.

Перед каждой записью агент:

1. Сверяет полные списки номеров рабочей ECF и `ECN ARCHIVE` (`6439007336484740`, колонка `ECN#` — `8114644527042436`). Проверяет полноту страниц и стабильность версии рабочей таблицы во время сверки архива.
2. Берёт максимум номера за нужный день с учётом сохранённых счётчиков и резервирует следующий номер за Row ID в SQLite. Пропуски в нумерации не заполняет.
3. Заново читает строку, проверяет пустой номер, статус, дату, версию таблицы и права на запись.
4. Отправляет один PUT, изменяющий только ячейку `ECN Number`. Статус, согласующие, форматирование и другие поля не меняются.
5. Читает результат, сохраняет событие «Присвоен номер ECN …» и обновляет снимок панели. За один цикл обрабатывается до пяти строк; остальные остаются до следующего цикла.

Если версия меняется во время сверки перед записью, агент повторяет чтение для этой строки с задержками 0,5, 1 и 2 секунды. При очередном расхождении он откладывает оставшуюся очередь до следующего цикла.

Блокировка отдельной строки или некорректная дата создания отражаются в журнале. Агент может обработать другие заявки в пределах лимита пяти проверяемых строк. Агент учитывает все занятые номера в рабочей ECF и архиве при расчёте максимума за день. Если у двух записей уже был одинаковый номер, агент отмечает повтор в журнале и продолжает выдавать свободные номера. Если номер незавершённого назначения обнаружен у другой строки или сама строка уже получила другой номер, агент останавливает цикл для сверки. Ошибка доступа к листу или колонке и недоступный архив также останавливают цикл. При новом цикле агент в первую очередь сверяет ранее отправленные, неподтверждённые и конфликтующие назначения.

Итог в журнале показывает число пустых строк Initial Review на момент отбора, количество присвоений и отложенных строк. В итог также входят записи из журнала назначений, если они ещё требуют сверки. Отдельно указаны ранее выданные номера, которые удалось подтвердить чтением, и строки, выбывшие из очереди. При остановке итог содержит причину и номер проверяемой строки или её Row ID, если порядковый номер недоступен.

Колонка ECN Number в рабочей таблице заблокирована, поэтому аккаунту токена требуется Admin или Owner. Если архив недоступен или ответ неполный, запись не выполняется.

Журнал назначений и счётчики хранятся в `data/numbering.sqlite`, отдельно от снимков `data/ecn.sqlite`. Резервирование переживает перезапуск и исчезновение строк. `data/numbering.sqlite.lock.sqlite` удерживает блокировку одного исполнителя; ОС освобождает её после остановки или аварийного завершения. Сохраняй обе основные базы при переносе и резервном копировании после остановки агента. Не удаляй журнал номеров для сброса ошибки: в нём могут быть ещё не подтверждённые записи.

Если ответ на PUT потерян, агент проверяет результат чтением и не повторяет неопределённую запись. Совпавший номер подтверждается автоматически. Если результат остаётся неизвестным или обнаружен конфликт, панель показывает причину и нумерация останавливается для сверки. Нужно проверить эту строку и ожидаемый номер в Smartsheet; когда ожидаемый номер обнаружен при следующей проверке, неопределённая операция завершается. Явно отклонённый сервером запрос может повториться в следующем цикле после всех проверок с тем же зарезервированным номером.

**Один источник присвоения номеров:** не запускай независимые копии агента и не присваивай номера вручную параллельно. API Smartsheet не предоставляет документированной операции «записать, только если ячейка всё ещё пуста». Повторное чтение уменьшает окно гонки, но не устраняет одновременную запись другим пользователем или сервисом. Локальная блокировка защищает экземпляры, использующие одну базу на одном компьютере.

## Работа с вложениями

Скрепка в таблице и вкладка «Вложения» открывают общий список вложений строки и её комментариев. У каждого элемента показан источник. Файлы и ссылки на внешние хранилища различаются в списке; внешнее хранилище может потребовать свою авторизацию.

Агент автоматически сохраняет только метаданные вложений. По нажатию «Открыть файл» запрашивается свежая ссылка Smartsheet и открывается отдельная вкладка браузера: просмотр или скачивание зависит от типа файла и ответа сервера. Временные ссылки не сохраняются в SQLite. Выбранные файлы дополнительно можно передать модели кнопкой «Разобрать ECN».

Первая успешная загрузка вложений создаёт исходный список без отдельных событий для каждого старого файла. Последующие добавления, исчезновения и изменения метаданных отражаются в журнале. Это сравнение списков, а не проверка содержимого файлов или загрузка истории их версий. Если файл уже удалён или потерян доступ, открытие покажет сообщение об ошибке; список обновится после успешной проверки.

## Как получаются комментарии и вложения

Каждый цикл:

1. Читает все страницы строк ECF с контактами согласующих.
2. Читает все страницы `GET /sheets/{sheetId}/discussions?include=comments`, включая ответы внутри обсуждений.
3. Проверяет число результатов, уникальность идентификаторов, наличие полных массивов комментариев и согласованность страниц. Для многостраничного списка обсуждений повторно сверяет первую страницу.
4. Читает все страницы `GET /sheets/{sheetId}/attachments`, проверяет полноту и уникальность ID; для нескольких страниц повторно сверяет первую. Вложения `ROW` привязываются к строкам, `COMMENT` — через ID комментариев к их ECN.
5. Повторно проверяет версию и число строк ECF, затем привязывает обсуждения с `parentType=ROW` к соответствующим Row ID.
6. Одной локальной транзакцией сохраняет строки, комментарии, метаданные вложений и события. При ошибке сохраняется предыдущий успешный снимок целиком.

Обсуждения проверяются независимо от `row.modifiedAt`. Изменения комментариев сравниваются по ID и содержимому, поэтому неизменившиеся сообщения не создают повторные события. Отдельные изменения во время последовательных запросов API могут быть обнаружены на следующем цикле; это периодическое наблюдение, а не поток событий в реальном времени.

Обсуждения уровня таблицы (`parentType=SHEET`), вложения самой таблицы и её общих комментариев не привязываются к отдельному ECN. Вложения `PROOF` не отображаются: связь proof с ECN в этом модуле не загружается. Из архива читаются только номера для автонумерации; его строки и обсуждения в панели не показываются.

При обновлении существующей базы добавляется таблица локальных отметок прочтения, если её ещё нет; прежние строки, события и настройки паузы сохраняются. Метаданные вложений добавляются к снимкам строк при следующей успешной проверке.

Если ECN исчезает из успешного полного снимка ECF, его текущая строка, комментарии, список вложений и отметки прочтения удаляются из локального списка. События журнала остаются. Причина исчезновения автоматически не устанавливается. Сохранение архивных снимков — отдельное будущее изменение.

## Границы операций и запуск на сервере

Режим наблюдения использует GET к фиксированной ECF. Автонумерация дополнительно читает номера из фиксированного архива и выполняет PUT одной ячейки `ECN Number` подходящей строки рабочей ECF. В локальном API доступны управление циклом, отметки прочтения и открытие вложения, принадлежащего выбранному ECN; произвольного редактирования Smartsheet нет. При открытии вложения браузер переходит по ссылке из Smartsheet; токен API остаётся на стороне Node.js.

Панель слушает `127.0.0.1`, проверяет Host/Origin и отклоняет управление с посторонних сайтов. Содержимое сообщений не выполняется как код. При загрузке ограничены попытки и время ожидания. Запускай один экземпляр с одной базой.

Корневой `project/app.js` не подключает этот модуль. Обновление репозитория при прежней команде запуска основного приложения не запускает нового агента. Для него нужен отдельный процесс. Настройки автодеплоя непосредственно на сервере проверяются отдельно.

Перенос выполняется после остановки локального процесса: код, отдельно секреты и остановленная база передаются на сервер. Для удалённого доступа к панели потребуются авторизация и HTTPS. Несколько параллельных исполнителей потребуют общей очереди и блокировок.

## Дальнейшее развитие по подходу Jarvis

Мы используем идеи [burnjohn/jarvis-agent](https://github.com/burnjohn/jarvis-agent/tree/264a3b14acbd7bede07943967ed628534323779d): движок владеет состоянием, наблюдает за изменениями, использует узкие инструменты и восстанавливается после остановки.

ИИ-разбор одной заявки учитывает поля, обсуждения, выбранные вложения и опубликованную версию локальных правил. Предложения и ссылки на источники сохраняются в отдельной базе SQLite. Английский текст можно добавить в черновик комментария.

Панель и будущий Telegram-бот будут работать с одним предложением. Подтверждение привязывается к точному действию и снимку данных, имеет срок действия, проверку пользователя и защиту от повторного исполнения. Перед записью данные перечитываются. **Переход в `Sent for Approvals` уже запускает существующую рассылку Smartsheet**, поэтому будет отдельным контролируемым действием.

Для локального Telegram предусмотрен отдельный бот, поскольку действующий бот проекта уже использует webhook. Удаление старого ECN Assistant (`extensions/ecn/`, его браузерное расширение, роутер и связанные подключения) остаётся отдельным изменением основного приложения; этот комплект его не удаляет.

## Проверки

```cmd
npm test
```

Автотесты работают на искусственных данных и покрывают чтение страниц, контакты, комментарии и вложения, некорректные/неполные ответы, сохранение последнего успешного снимка, обновление старой структуры базы, прочтение по точной версии, перезапуск, паузу и локальный API. Для вложений проверяются привязка к ECN, журнал изменений и получение свежих ссылок без сохранения временных URL.

Для нумерации дополнительно проверяются два условия отбора, часовой пояс даты создания, архивные номера, изменение строки перед записью, неопределённый результат PUT, повторный запуск и блокировка второго исполнителя. Тесты никогда не записывают данные в настоящую ECF.

Для проверки реальной загрузки обсуждений и вложений нужен локальный запуск с твоим токеном.
