# ECN Agent — шаг 1

Локальная веб-панель и наблюдение за рабочей таблицей **ECF**, Sheet ID `5485143814104964`.

Это первый работающий слой нового агента. Он загружает ECN, показывает текущих согласующих, обнаруживает изменения и сохраняет журнал. Анализ через LLM, вопросы владельцу, Telegram и выполнение изменений будут следующими шагами. В этом комплекте нет вызовов модели или Telegram.

## 1. Размести файлы

Распакуй архив. Скопируй содержащуюся в нём папку `agents` в корень своего локального репозитория `project`. Если `agents` уже существует, добавь в неё подпапку `ecn-agent`.

Получится путь `project/agents/ecn-agent/package.json`.

Новый модуль запускается собственным `package.json`. Корневой `project/app.js` запускает действующее приложение, MongoDB и Telegram webhook. Для этого шага запускай команду именно из `agents/ecn-agent`.

## 2. Проверь Node.js

В терминале:

```powershell
node --version
```

Этот комплект рассчитан на **Node.js 24 LTS или новее**. Рекомендуемый вариант для первого запуска — последняя версия ветки 24 LTS с [официального сайта Node.js](https://nodejs.org/en/download). После установки открой новое окно терминала.

Зависимости входят в Node.js. Установка npm-пакетов для этого модуля не требуется.

## 3. Создай локальный .env

В Windows PowerShell, находясь в папке `project`:

```powershell
cd .\agents\ecn-agent
Copy-Item .env.example .env
notepad .env
```

Копирование `.env.example` выполняется при первой настройке. При повторных запусках используй уже заполненный `.env`.

На macOS/Linux:

```bash
cd agents/ecn-agent
cp .env.example .env
```

Открой `.env` в редакторе и заполни:

```dotenv
SMARTSHEET_API_TOKEN=вставь_свой_токен_здесь
ECN_PORT=4310
ECN_POLL_SECONDS=120
```

Используй токен аккаунта, которому доступна рабочая ECF. Сохрани файл. Значение токена остаётся на ноутбуке; в переписку достаточно присылать текст ошибки без секретов.

Sheet ID уже задан в `src/config.js`. Column ID основных полей и согласующих находятся в `src/smartsheet.js` и взяты из предоставленного контекста ECF. При несовпадении колонок панель покажет ошибку или предупреждение вместо подстановки данных из другой колонки.

## 4. Запусти

Из папки `project/agents/ecn-agent`:

```powershell
npm start
```

Если PowerShell сообщает о запрете выполнения `npm.ps1`, используй:

```powershell
npm.cmd start
```

Открой [http://127.0.0.1:4310](http://127.0.0.1:4310).

Окно терминала должно оставаться открытым. При выключении или сне ноутбука наблюдение приостанавливается; после запуска приложение перечитает таблицу. Изменения, которые успели появиться и исчезнуть между проверками, такой способ наблюдения может не увидеть.

## 5. Проверь первый результат

Успешный запуск выглядит так:

1. В панели появился статус «Наблюдение активно».
2. Видно время последнего успешного снимка и количество строк ECF.
3. Появились ECN, их статусы и материалы.
4. По нажатию на номер ECN открывается карточка с описанием и текущими согласующими.
5. В журнале есть запись «Загружен первый снимок ECF».

Первая загрузка создаёт исходный снимок. Старые строки не объявляются новыми ECN. Следующие проверки фиксируют появления, исчезновения и изменения отслеживаемых полей.

Счётчик «Активные ECN» исключает `Complete and Closed`, `Deleted/Canceled`, `Declined`. Эти строки доступны через фильтр «Все строки». Статусы вроде `Declined - Awaiting Update` остаются активными. Метки `createdAt` и `modifiedAt` относятся к строке Smartsheet.

Кнопка «Пауза» сохраняет паузу автопроверки, включая перезапуск приложения. Уже выполняющийся запрос завершится. Кнопка «Проверить сейчас» на паузе выполняет одну проверку. «Продолжить» снова включает автоматическое наблюдение.

Для завершения нажми `Ctrl+C` в терминале и дождись выхода процесса. Он завершит текущую загрузку перед закрытием базы; максимальное время одной загрузки ограничено 90 секундами.

Вложения, комментарии, история Smartsheet и остальные поля на этом этапе не загружаются. Локальная база содержит рабочие данные ECF; хранить её следует так же, как рабочие выгрузки таблицы.

## Ограничения операций в этом шаге

Адаптер Smartsheet предоставляет только чтение через `GET` фиксированной ECF. Кнопки панели управляют локальным циклом наблюдения. Маршрутов изменения ECN в комплекте нет. Это ограничение реализовано в коде; сам токен Smartsheet при этом может обладать более широкими правами аккаунта.

Панель слушает `127.0.0.1` и доступна на этом ноутбуке. API отклоняет запросы с посторонним Origin/Host. Токен не передаётся в браузер и не включается в сообщения ошибок.

Каждая полная загрузка сохраняется одной транзакцией. При ошибке, изменении версии между страницами или неполном ответе остаётся предыдущий успешный снимок. Число повторов и длительность запроса ограничены. Одновременные запросы обновления внутри одного процесса объединяются в один цикл.

Запускай один экземпляр приложения с этой базой. Защита нескольких процессов или серверов от конкурирующих изменений потребуется до подключения инструментов записи.

## Следующие небольшие шаги

### Шаг 2 — анализ и предложения

Добавляем одну рабочую роль агента для ECN. Она получает данные строки, утверждённые правила и матрицу согласующих. Архивные примеры помогают объяснять решения, но не заменяют действующие правила.

Результат анализа сохраняется как задача с конкретным предложением: что изменить, на основании каких полей и правил, что отсутствует, какие вопросы требуют ответа. В панели показываются входные данные, предложенные изменения, краткое обоснование и результат проверок. Скрытый ход рассуждений модели сохранять или показывать не требуется.

Тексты ECN и вложений рассматриваются как данные, а не инструкции агенту. Модель получает ограниченный контекст и возвращает результат по схеме. Секреты и произвольный доступ к Smartsheet модели не предоставляются. Для анализа задаются лимиты попыток, времени и расходов; при нехватке данных задача переходит в ожидание ответа. Другие ECN продолжают обрабатываться.

### Шаг 3 — подтверждения в панели и Telegram

Оба интерфейса работают с одним сохранённым предложением. Например:

> ECN 20261117-03. Предлагаю назначить следующих согласующих и перевести ECN в Sent for Approvals. Основание — такие-то поля ECF и пункты матрицы. Подтвердить / Исправить / Отклонить.

Предложение фиксирует Row ID, конкретные контакты, ожидаемые значения полей, срок действия и версию правил. Подтверждение разрешает именно это действие. Ответы принимаются от заданного Telegram user ID/chat ID. Повторное нажатие не создаёт новое выполнение. Ответ, меняющий состав согласующих, создаёт новую версию предложения для просмотра.

На ноутбуке можно принимать сообщения через `getUpdates` — исходящие HTTPS-запросы к Telegram. В существующем `project/app.js` бот уже использует webhook, а Telegram не позволяет одновременно получать обновления одного бота через webhook и `getUpdates`. Для нового агента заведём отдельного бота. Подробнее — [Telegram Bot API](https://core.telegram.org/bots/api#getupdates).

### Шаг 4 — контролируемая запись в рабочую ECF

Вводим отдельные инструменты с проверками для каждой операции. Номер ECN формируется детерминированно по согласованной дате и часовому поясу, с проверкой коллизий и защитой единственного исполнителя. Модель не вычисляет следующий порядковый номер самостоятельно.

Перед выполнением предложение повторно сверяется с актуальной строкой. Если важные поля или согласующие изменились после подтверждения, требуется обновлённое предложение. При неясном результате запроса после сбоя движок сначала перечитывает ECF и сопоставляет фактический результат с планом.

Для отправки на согласование порядок будет таким: записать и проверить полный состав согласующих, затем выполнить разрешённый переход статуса. **Смена статуса на `Sent for Approvals` уже запускает существующую рассылку Smartsheet**. Поэтому этот переход учитывается как действие с внешними последствиями. Сам агент не должен дублировать запросы согласующим.

Политики автономности будут различаться по операциям. Анализ и проверки могут выполняться самостоятельно; отправка на согласование на первом этапе требует подтверждения конкретного предложения. После накопления проверенных результатов можно разрешать отдельные действия по явным правилам. Оценка уверенности модели сама по себе не даёт разрешение на действие.

## Старый ECN Assistant

Новый запуск использует только содержимое `agents/ecn-agent`. Старый помощник подлежит отдельному удалению из основного приложения.

По проверенному GitHub-состоянию `TheMainOne/project` на commit `8ddaa49dd56ec03ea59f5cb7eae7233eb8c84059` удаление затрагивает:

- `extensions/ecn/` — старый ECN-модуль.
- `extensions/clients/chrome-smartsheet-ecn/` — его браузерное расширение.
- `extensions/api/ecnExt.js` — старый роутер.
- `script/ecnImport.js`, `script/ecnActivate.js` и соответствующие npm scripts.
- Старые `test/ecn*.test.js`.
- Импорт и подключение роутера ECN в `app.js`.
- ECN-специфичные scopes/проверки выдачи extension token в auth-контроллере и валидаторе.

Общая авторизация расширений используется также другими функциями проекта. Для удаления подготовим точный diff после сверки локальных файлов с GitHub. Этот архив содержит новые файлы и не применяет удаление автоматически. Локальные изменения ноутбука в доступном окружении не просматривались.

## Перенос на сервер

SQLite выбрана для первого этапа, чтобы состояние хранилось в переносимом файле. Для переноса потребуется остановить локальный процесс, дождаться завершения проверки и скопировать код, локальную конфигурацию и `data/ecn.sqlite` на сервер с подходящей версией Node.js. Секреты передаются отдельно от Git. Запуск на сервере начинается после остановки локального экземпляра.

Перед доступом к панели через интернет добавим авторизацию, HTTPS, управление процессом и резервное копирование. В текущем виде панель предназначена для локального просмотра. При появлении нескольких исполнителей отдельно спроектируем общую очередь и блокировки; простого копирования базы между работающими экземплярами для этого недостаточно.

## Проверки и диагностика

Из папки `agents/ecn-agent`:

```powershell
npm test
```

В комплекте 13 проходящих автотестов на искусственных данных: постраничное чтение, версии и неполные ответы, контакты, ограничение запросов, сохранение снимков, транзакционный откат, перезапуск, пауза и локальный HTTP API. Также проверены синтаксис всех JavaScript-файлов, запуск без токена и корректное завершение процесса на Node.js 24.

Подключение к реальной ECF будет проверено после ввода токена на ноутбуке. Браузерную проверку в среде подготовки завершить не удалось: локальный Chromium не запустился, а отдельный браузер не получил доступ к локальному серверу. Поэтому внешний вид и нажатия кнопок нужно подтвердить при первом локальном запуске.

| Сообщение | Что проверить |
| --- | --- |
| «Нужен API-токен» | Файл именно `agents/ecn-agent/.env`, значение заполнено, процесс перезапущен |
| «Smartsheet отклонил токен» | Токен действующий, скопирован полностью |
| «Нет доступа к ECF» / «ECF не найдена» | Аккаунт токена имеет доступ к указанной рабочей таблице |
| «Отсутствуют ожидаемые поля» | Column ID в ECF; передать названия отсутствующих полей для сверки |
| «ECF изменилась во время чтения» | Дождаться следующего цикла; при постоянном повторении сообщить текст ошибки |
| «Порт занят» | Уже открытый экземпляр или другой процесс; изменить `ECN_PORT` при необходимости |
| «Нет связи с локальным агентом» | Терминал работает, ноутбук не спит, адрес и порт совпадают |

Технические источники: [Node.js SQLite](https://nodejs.org/download/release/latest-v24.x/docs/api/sqlite.html), [Smartsheet Get Sheet](https://developers.smartsheet.com/api/smartsheet/openapi/sheets/getsheet), [Telegram Bot API](https://core.telegram.org/bots/api).
