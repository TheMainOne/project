# ECN Agent v0.3

Локальная панель наблюдения за рабочей **Engineering Change Form (ECF)**. Sheet ID `5485143814104964`.

**Если предыдущая версия уже работает, начни с [UPDATE_RU.md](UPDATE_RU.md).** Существующие `.env`, база и журнал сохраняются при обновлении. Ниже — устройство модуля и инструкция первого запуска.

## Возможности

- Компактная таблица в стиле Smartsheet: номера строк, закреплённый номер ECN, статусы, площадки, материалы и описания.
- Поиск, фильтры, сортировка по порядку ECF, изменению строки и активности обсуждений; страницы по 100 строк.
- Боковая карточка с данными ECN, описанием изменения и текущими согласующими.
- Обсуждения ECN с авторами, датами, ответами и датами редактирования.
- Обнаружение новых, отредактированных и исчезнувших комментариев при каждой проверке.
- Сохраняемые отметки новых/изменённых сообщений, фильтр «Новые комментарии».
- Вложения строки и её комментариев: скрепка со счётчиком, фильтр «С вложениями», отдельная вкладка с названием, размером, автором и датой.
- Открытие файла или внешней ссылки по свежему адресу из Smartsheet; журнал добавлений, удалений и изменений метаданных вложений.
- Журнал последних 100 событий в интерфейсе; более ранние события остаются в SQLite.
- Пауза, ручная проверка и восстановление после остановки.

На этом этапе приложение наблюдает за ECF. Вызовов LLM, Telegram и инструментов изменения Smartsheet пока нет.

## Первый запуск

Нужен Node.js 24 или новее. Для этого комплекта подходит Node.js 24 LTS с [официального сайта](https://nodejs.org/en/download).

Помести папку `agents` из архива в корень локального `project`. Должен появиться путь `project/agents/ecn-agent/package.json`.

В Windows CMD из корня `project`:

```cmd
cd agents\ecn-agent
copy .env.example .env
notepad .env
```

На macOS/Linux вместо `copy` используй `cp`. Шаблон копируется только при первой настройке. Если `.env` уже заполнен, используй его.

В `.env`:

```dotenv
SMARTSHEET_API_TOKEN=твой_токен_Smartsheet
ECN_PORT=4310
ECN_POLL_SECONDS=120
```

Токен хранится в **`agents/ecn-agent/.env`**. Корневой `project/.env` относится к основному приложению. `.env.example` — шаблон с пустым токеном, пригодный для Git.

Из папки `agents/ecn-agent`:

```cmd
npm start
```

Открой [http://127.0.0.1:4310](http://127.0.0.1:4310). Если PowerShell блокирует `npm.ps1`, запускай `npm.cmd start`. Зависимости входят в Node.js, установка дополнительных пакетов не требуется.

Пока агент работает, терминал должен быть открыт. Для остановки нажми `Ctrl+C` и дождись выхода. Текущая загрузка ограничена 90 секундами. При сне или выключении ноутбука наблюдение приостанавливается. После запуска приложение получает новый снимок; промежуточные изменения между проверками могут быть не видны.

## Работа с панелью

Номер ECN открывает вкладку «Данные ECN». Значок обсуждения открывает вкладку «Комментарии». Вторая вкладка автоматически показывает новые данные после успешной проверки. Поиск работает по номеру ECN, материалу, описанию материала, площадке, статусу и инициатору.

Синий индикатор означает новые или изменённые комментарии, которые ещё не открывались в этой локальной панели. Первоначальная загрузка существующей переписки создаёт исходное состояние без уведомлений о каждом старом сообщении. Последующее открытие вкладки «Комментарии» сохраняет отметку прочтения именно показанного снимка. Если данные успели измениться, новый снимок остаётся непрочитанным до отображения. Это локальная отметка, общая для окон этой панели; она не изменяет Smartsheet.

Обсуждения упорядочены по времени последнего добавленного сообщения, ответы внутри обсуждения — по дате создания. Дата правки показана отдельно. Авторское форматирование HTML не исполняется: тексты выводятся как обычный текст.

«Пауза» сохраняется после перезапуска. Выполняющаяся проверка завершается. «Проверить сейчас» на паузе выполняет один цикл. «Продолжить» возобновляет автопроверку. Интервал по умолчанию 120 секунд отсчитывается после завершения предыдущего цикла.

«Активные ECN» исключает статусы `Complete and Closed`, `Deleted/Canceled`, `Declined`. Остальные строки доступны через «Все строки». Время создания/изменения строки берётся из Smartsheet и не подменяется временем сообщения. Пустая площадка остаётся пустой; агент не угадывает её.

## Работа с вложениями

Скрепка в таблице и вкладка «Вложения» открывают общий список вложений строки и её комментариев. У каждого элемента показан источник. Файлы и ссылки на внешние хранилища различаются в списке; внешнее хранилище может потребовать свою авторизацию.

Агент автоматически сохраняет только метаданные вложений. По нажатию «Открыть файл» запрашивается свежая ссылка Smartsheet и открывается отдельная вкладка браузера: просмотр или скачивание зависит от типа файла и ответа сервера. Временные ссылки не сохраняются в SQLite. Содержимое файлов не скачивается в фоне и не анализируется.

Первая успешная загрузка вложений создаёт исходный список без отдельных событий для каждого старого файла. Последующие добавления, исчезновения и изменения метаданных отражаются в журнале. Это сравнение списков, а не проверка содержимого файлов или загрузка истории их версий. Если файл уже удалён или потерян доступ, открытие покажет сообщение об ошибке; список обновится после успешной проверки.

## Как получаются комментарии и вложения

Каждый цикл:

1. Читает все страницы строк ECF с контактами согласующих.
2. Читает все страницы `GET /sheets/{sheetId}/discussions?include=comments`, включая ответы внутри обсуждений.
3. Проверяет число результатов, уникальность идентификаторов, наличие полных массивов комментариев и согласованность страниц. Для многостраничного списка обсуждений повторно сверяет первую страницу.
4. Читает все страницы `GET /sheets/{sheetId}/attachments`, проверяет полноту и уникальность ID; для нескольких страниц повторно сверяет первую. Вложения `ROW` привязываются к строкам, `COMMENT` — через ID комментариев к их ECN.
5. Повторно проверяет версию и число строк ECF, затем привязывает обсуждения с `parentType=ROW` к соответствующим Row ID.
6. Одной локальной транзакцией сохраняет строки, комментарии, метаданные вложений и события. При ошибке сохраняется предыдущий успешный снимок целиком.

Обсуждения проверяются независимо от `row.modifiedAt`. Изменения комментариев сравниваются по ID и содержимому, поэтому неизменившиеся сообщения не создают повторные события. Отдельные изменения во время последовательных запросов API могут быть обнаружены на следующем цикле; это периодическое наблюдение, а не поток событий в реальном времени.

Обсуждения уровня таблицы (`parentType=SHEET`), вложения самой таблицы и её общих комментариев не привязываются к отдельному ECN. Вложения `PROOF` не отображаются: связь proof с ECN в этом модуле не загружается. Архивная таблица пока не читается.

## Файлы

| Путь | Назначение |
| --- | --- |
| `package.json` | Самостоятельные команды запуска и тестов |
| `.env.example`, `.gitignore` | Шаблон настроек и исключение секретов/данных из Git |
| `src/config.js` | Sheet ID, локальный порт, интервал и путь базы |
| `src/smartsheet.js` | Чтение ECF, обсуждений и вложений с проверкой полноты; свежие ссылки на открытие |
| `src/comments.js` | Сравнение содержимого комментариев и подсчёт непрочитанных |
| `src/store.js` | Снимки, комментарии, метаданные вложений, локальные отметки прочтения и журнал |
| `src/monitor.js` | Цикл проверки, пауза, объединение параллельных запросов |
| `src/http.js` | Локальный API панели |
| `src/server.js` | Запуск и корректное завершение |
| `public/` | Таблица, боковая карточка, обсуждения, вложения, журнал |
| `tests/` | Проверки на искусственных данных |

База создаётся в `data/ecn.sqlite`. Она содержит рабочие поля ECF, контакты, тексты комментариев, метаданные вложений и журнал. Храни её как рабочую выгрузку ECF. При обновлении существующей базы добавляется таблица локальных отметок прочтения, если её ещё нет; прежние строки, события и настройки паузы сохраняются. Метаданные вложений добавляются к снимкам строк при следующей успешной проверке.

Если ECN исчезает из успешного полного снимка ECF, его текущая строка, комментарии, список вложений и отметки прочтения удаляются из локального списка. События журнала остаются. Причина исчезновения автоматически не устанавливается. Сохранение архивных снимков — отдельное будущее изменение.

## Границы операций и запуск на сервере

Внешние API-запросы используют только GET к фиксированной ECF. В локальном API доступны управление циклом, отметки прочтения и открытие вложения, принадлежащего выбранному ECN. При открытии браузер переходит по ссылке из Smartsheet; токен API остаётся на стороне Node.js. Его собственные права в Smartsheet могут быть шире возможностей этого приложения.

Панель слушает `127.0.0.1`, проверяет Host/Origin и отклоняет управление с посторонних сайтов. Содержимое сообщений не выполняется как код. При загрузке ограничены попытки и время ожидания. Запускай один экземпляр с одной базой.

Корневой `project/app.js` не подключает этот модуль. Обновление репозитория при прежней команде запуска основного приложения не запускает нового агента. Для него нужен отдельный процесс. Настройки автодеплоя непосредственно на сервере проверяются отдельно.

Перенос выполняется после остановки локального процесса: код, отдельно секреты и остановленная база передаются на сервер. Для удалённого доступа к панели потребуются авторизация и HTTPS. Несколько параллельных исполнителей потребуют общей очереди и блокировок.

## Дальнейшее развитие по подходу Jarvis

Мы используем идеи [burnjohn/jarvis-agent](https://github.com/burnjohn/jarvis-agent/tree/264a3b14acbd7bede07943967ed628534323779d): движок владеет состоянием, наблюдает за изменениями, использует узкие инструменты и восстанавливается после остановки.

Следующий слой — сохранённые задачи анализа ECN с учётом полей, обсуждений и утверждённых правил. Текст комментария будет входными данными, а не инструкцией, отменяющей ограничения агента. Модель сможет задавать вопросы, формировать обоснованные предложения согласующих и ожидаемых изменений; исполнение будет проходить отдельные проверки.

Панель и будущий Telegram-бот будут работать с одним предложением. Подтверждение привязывается к точному действию и снимку данных, имеет срок действия, проверку пользователя и защиту от повторного исполнения. Перед записью данные перечитываются. **Переход в `Sent for Approvals` уже запускает существующую рассылку Smartsheet**, поэтому будет отдельным контролируемым действием.

Для локального Telegram предусмотрен отдельный бот, поскольку действующий бот проекта уже использует webhook. Удаление старого ECN Assistant (`extensions/ecn/`, его браузерное расширение, роутер и связанные подключения) остаётся отдельным изменением основного приложения; этот комплект его не удаляет.

## Проверки

```cmd
npm test
```

Автотесты работают на искусственных данных и покрывают чтение страниц, контакты, комментарии и вложения, некорректные/неполные ответы, сохранение последнего успешного снимка, обновление старой структуры базы, прочтение по точной версии, перезапуск, паузу и локальный API. Для вложений проверяются привязка к ECN, журнал изменений и получение свежих ссылок без сохранения временных URL.

Для проверки реальной загрузки обсуждений и вложений нужен локальный запуск с твоим токеном.

Технические источники: [Smartsheet List Discussions](https://developers.smartsheet.com/api/smartsheet/openapi/discussions/discussions-list), [Smartsheet Comments](https://developers.smartsheet.com/api/smartsheet/openapi/comments), [List Attachments](https://developers.smartsheet.com/api/smartsheet/openapi/attachments/attachments-listonsheet), [Get Attachment](https://developers.smartsheet.com/api/smartsheet/openapi/attachments/attachments-get), [Node.js SQLite](https://nodejs.org/download/release/latest-v24.x/docs/api/sqlite.html).
