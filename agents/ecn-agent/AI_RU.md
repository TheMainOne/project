# ИИ-разбор ECN

В карточке заявки открой **ИИ-разбор**, отметь нужные вложения и нажми **Разобрать ECN**. По умолчанию выбор файлов пуст для заявки без прежнего разбора. Агент покажет, что просит инициатор, какие материалы и площадки затронуты, каких сведений не хватает и какие действия или согласования стоит рассмотреть. Под каждым выводом можно развернуть его источники. Для файла доступна ссылка на оригинал в этом ECN.

**Добавить в черновик** переносит английский текст в поле комментария, сохраняя уже набранный текст и выбранный файл. Отправка в Smartsheet выполняется существующей кнопкой **Отправить**. Номера ECN назначает действующий модуль автонумерации.

## Подключение в Windows

1. Останови работающий агент сочетанием Ctrl+C. Распакуй архив кода, а затем отдельный комплект знаний в корень `project`. Оба начинаются с `agents/ecn-agent/`.
2. Добавь в существующий `agents/ecn-agent/.env` две строки. В первой укажи свой ключ проекта OpenAI. Для нового каталога образец настроек лежит в `.env.example`.
   
   ```dotenv
   OPENAI_API_KEY=
   OPENAI_MODEL=gpt-5.4-mini
   ```
3. Из каталога `project/agents/ecn-agent` выполни `npm.cmd test`, затем `npm.cmd start`. Открой привычный адрес панели. После смены ключа или модели перезапусти процесс. Нужна модель Responses API с поддержкой изображений и Structured Outputs.

Сервер читает ключ из окружения или `.env`. Содержимое файла `.env` имеет приоритет, как и в прежних версиях агента. Модель, указанная в карточке, соответствует текущему значению настройки. Открытие карточки, опрос ECF и публикация базы знаний работают локально относительно OpenAI. Только кнопка разбора инициирует обращение к модели.

## Что передаётся в OpenAI

Поля выбранной строки, включая заполненные контактные поля, текст и авторы обсуждений этой строки, до шести подходящих фрагментов локальной базы и содержимое выбранных файлов. Подбор фрагментов выполняется на компьютере по описанию, площадке, материалу, недавним комментариям и названиям выбранных файлов. Сами вложения модель читает при разборе. Передача идёт через Responses API с `store: false`. Для рабочих ECN используй API-проект и состав данных, разрешённые для этой работы в DWK.

Файлы выбираются из вложений строки и её комментариев. Поддерживаются PDF, DOCX, XLSX, CSV, TXT, PNG, JPEG и WebP. Лимиты приложения составляют 5 файлов за раз, 12 МиБ на файл и 20 МиБ в сумме. Агент получает от Smartsheet временный адрес каждого файла. В OpenAI передаются байты файла. Для внешней ссылки из Drive или OneDrive в списке показывается причина её недоступности.

Для чертежей с размерами или графикой удобен PDF. OpenAI использует текст и страницы PDF. Для DOCX извлекается текст, а для электронной таблицы обрабатывается до первых 1 000 строк каждого листа. Встроенные изображения Office лучше приложить отдельным PDF или изображением. Обсуждения передаются с приоритетом последних изменений, в пределах 60 сообщений и 36 000 символов суммарно. Если сработал лимит, это видно в разборе. [Обработка файлов в Responses API](https://developers.openai.com/api/docs/guides/file-inputs)

Ответ сохраняется в `data/ai-reviews.sqlite` вместе с версией базы, моделью, источниками и выбранными файлами. Сервер проверяет, что упомянутые моделью идентификаторы действительно присутствовали в запросе. Точность интерпретации проверяет координатор по раскрываемым источникам. При изменении снимка, модели или базы предыдущий ответ получает отметку «Разбор устарел». Повтор для тех же данных открывает сохранённый результат. При повторе с выбранными файлами агент сначала сверяет их содержимое. Если Smartsheet изменился после последней синхронизации, панель узнает об этом при получении следующего снимка. Кнопка «Проверить сейчас» выполняет обычную проверку ECF с текущими настройками автонумерации.

## Где хранить и обновлять знания

Рабочая папка одного установленного агента — `data/knowledge/`. Она исключена из Git. Для командной работы держите оригиналы документов и историю их редакций в закрытом корпоративном хранилище, например в библиотеке SharePoint с версионированием. Локальная публикация определяет, какая редакция доступна этому экземпляру агента.

| Что хранится | Где | Для чего |
| --- | --- | --- |
| Рабочие файлы Word, Markdown и CSV матрицы | `sources/` | Владелец редактирует и проверяет материалы |
| Список используемых документов и редакций | `sources/manifest.json` | Указывает файл, стабильный ID, название, тип и ревизию каждого источника |
| Копии обработанных исходников | `originals/` | Открытие первоначального файла по его SHA-256 из индекса версии |
| Опубликованные версии | `versions/<SHA-256>.json` | Точные тексты разделов и таблиц, их источники и редакции |
| Активная версия | `active.json` | Выбор версии для новых разборов |

Стартовый комплект содержит рабочее руководство Master Data Coordinator v1.2, проект правил ECN Agent v0.1 и 25 строк матрицы DWKID-7206 Rev. 5. В каждой строке матрицы отдельно указаны подразделения для Pre-Approval, Implementation Review и Completion Notification. Чтобы назвать предполагаемых согласующих, модель должна сослаться на факт из этого ECN и на применимый источник процедур. Проект правил агента и архивные примеры используются как справочные сведения. При расхождении источников в разборе требуется уточнение. Выбор конкретного сотрудника зависит от площадки, типа изменения и действующих назначений.

### Публикация новой редакции

1. В рабочем справочнике опиши правило, область действия, исключения, источник решения, владельца и дату подтверждения. Случай из одного ECN можно хранить отдельным Markdown-файлом со ссылкой на ECN и типом `precedent`. Черновики допускается держать рядом с источниками, публикация берёт файлы из списка в манифесте.
2. Положи проверенную редакцию в `sources/`. В соответствующей записи `manifest.json` обнови `revision` и, если изменилось имя, `file`. Для нового документа добавь запись с новым `id`. Допустимые типы — `procedure` (процедура), `handbook` (руководство), `guidance` (рабочие указания), `precedent` (отдельный случай). В DOCX заголовки оформляй стилями Word Heading 1–6, в Markdown — заголовками с решёткой.
3. Из каталога агента выполни `npm.cmd run kb:publish`. Команда работает локально. Для чтения Word, публикации и запуска агента достаточно Node.js 24 или новее.
4. На вкладке «ИИ-разбор» раскрой «База знаний» и проверь новую редакцию. Перезапуск агента после публикации не требуется.

**Обновление матрицы.** В авторитетном Excel-файле открой лист самой матрицы (в Rev. 5 это Sheet1). Сохрани этот лист как CSV UTF-8 и положи в `sources/` под именем из манифеста. Укажи точный номер редакции из строки Revision No. Импорт сверяет DWKID-7206, ревизию, названия этапов и значения YES/NO. Он извлекает распределение подразделений по этапам до журнала ревизий. Если структура новой матрицы изменилась и проверка остановилась, действующей остаётся ранее опубликованная версия.

**Восстановление.** Сохраняй резервную копию папки `data/knowledge/` и базы `data/ai-reviews.sqlite` при остановленном агенте. Чтобы вернуться к прежней публикации, запиши в `active.json` объект `{"version":"полный SHA-256 нужной версии"}`, выбрав существующий файл из `versions/`. Ранее сохранённый разбор хранит тексты использованных источников. Для следующих плановых изменений верни соответствующие оригиналы в `sources/` и поправь редакции в манифесте.
